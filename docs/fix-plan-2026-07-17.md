## 关键前置: 运行环境 (FIX-0)

用户反馈在 http://localhost:1420/ 打开 —— 这是 Vite 前端开发服务器, 没有 Rust 后端。
所有 invoke(...) 调用都会失败, listen(...) 收不到后端事件。这是大量"失效"的根因。

**必须用 `npm run tauri dev` 启动**, 它会同时起 Vite + Rust 后端 + 桌面窗口(无地址栏)。

附加防护 (建议前端加):
- 检测 `window.__TAURI__` 是否存在; 不存在时显示一次性提示气泡:
  "请在桌面模式下运行 (npm run tauri dev)", 避免再次误判。

## 逐项修复清单

### FIX-A: 视线不回正 (用户 2.3)
- **现象**: 鼠标移到屏幕角落, 模型视线一直盯着角落, 不回正。
- **根因 (已验证)**:
  1. `pixi-live2d-display` 库内置全局鼠标追踪, 每帧自动调用 `model.focus(mouseX, mouseY)` 更新头部/眼球参数。
  2. 我们自己的 `computeAttention()` / `computeHeadAngle()` (src/animation/attention.ts) 正确算了三态和角度, 但结果只存进 React `attention` state, **从未传给 Live2DCanvas**, 也从未调用 `model.focus()`。
  3. 两套系统并行, 库的追踪永远胜出, Ignored 态的"归零"逻辑被忽略。
- **修复**:
  - Live2DCanvas 接收 `attention` + 鼠标坐标(或 angleX/angleY) 作为 props。
  - 在 `app.ticker` 每帧手动 `model.focus(targetX, targetY)`:
    - Focused / Peripheral: 按鼠标相对模型中心的位置算 target。
    - Ignored: target = 模型自身中心 (视线回正)。
  - 需验证库的自动追踪是否被覆盖; 若冲突, 改为操作 `model.internalModel.focusController` 或禁用 stage 的 pointermove 自动聚焦。
- **验收**: 鼠标靠近角落 → 视线跟随; 鼠标移开 >200px → 约 1 秒内视线平滑回到正前方。
- **文件**: src/Live2DCanvas.tsx, src/App.tsx

### FIX-B: FSM 微行为无法驱动模型 (用户 第四节)
- **现象**: 自动切换微行为(look_around/yawn/stretch 等)在模型上完全看不到。
- **根因 (已验证)**:
  1. FSM 逻辑正确 (src/animation/fsm.ts), 每 2.5s tick 更新 `behavior` state。
  2. CSS 动画类 (`.pet-svg.look-around` 等) 绑定的是 `.pet-svg` 元素, 但渲染用的是 Live2D `<canvas>`, **不存在 `.pet-svg`**。
  3. `behavior` state **从未传给 Live2DCanvas**, 也没有 FSM→Live2D motion 的映射表。
- **修复**:
  - Live2DCanvas 接收 `behavior: BehaviorState` prop。
  - 建 `FSM_TO_MOTION` 映射 (注意 Haru model3.json 只定义了 Idle×3 + Tap×2 两组 motion, 见 public/live2d/models/haru/haru_greeter_t03.model3.json):
    - LookAround / TiltHead / Stretch / Peek → `model.motion("Tap")` (随机 index) + 可叠加 expression。
    - Yawn / Sleeping → expression f05/f06 (困倦类)。
    - Idle → 不主动触发, 让库的 idle + 呼吸运行。
    - Talking / Thinking 由对话流单独处理 (见 FIX-F/G)。
  - 用 ref 记录上次 behavior, 避免重复触发同一 motion。
- **验收**: 每 2.5s tick 在模型上可见明显的动作/表情变化。
- **文件**: src/Live2DCanvas.tsx, src/App.tsx, 可能微调 src/animation/fsm.ts

### FIX-C: 戳身体无反应 (用户 2.6)
- **现象**: 单击身体不切换动作, 看不到任何反应。
- **根因 (已验证)**: `handleBodyClick` 只调用 `invoke("poke")` 更新后端, 第 3 次才冒泡; 没有调用 FSM transition, 也没有触发任何 Live2D 动作。
- **修复**:
  - 每次戳都给反馈: `fsmRef.current.transition(BehaviorState.Embarrassed)` (借 FIX-B 的映射触发动作)。
  - 分级气泡: 1 次 → "?" (惊讶), 2 次 → "嗯…" (皱眉, bubble-worried), 3 次 → "别戳了啦!" (生气)。
- **验收**: 每次戳身体都有可见动作 + 气泡。
- **文件**: src/App.tsx

### FIX-D: 输入框 placeholder 看不见 (用户 2.8)
- **现象**: 双击出现输入框, 但看不到"想和我说什么?"。
- **根因 (已验证)**: `.input-bubble input::placeholder { color: rgba(255,255,255,0.35) }` 白字; 气泡背景近白 → 白字白底不可见。
- **修复**: `color: rgba(120,120,140,0.6)` (灰字)。
- **验收**: placeholder 清晰可见。
- **文件**: src/styles.css

### FIX-E: 拖拽 + 物理渲染完全失效 (用户 2.10 / 第十节)
- **现象**: 左键按住无法拖动; 自由落体/弹跳/空间记忆全部看不到。
- **根因 (已验证, 三重)**:
  1. `handleDragStart` 调用 `getCurrentWindow().startDragging()` —— 这是 Tauri API, 移动的是**整个操作系统窗口**, 不是窗口内的角色。浏览器模式下不存在的 API 直接抛错。
  2. `handleDragStart` **从未调用 `setIsBeingDragged(true)`**, 所以依赖 `isBeingDragged` 的 useEffect(监听 mousemove/mouseup + `physics.release()`)永远不会运行 —— 拖拽状态机本身是死的。
  3. `petPos` state 被 Physics/Spatial 更新, 但 **从未应用到任何 DOM 元素**。`.pet-char-wrapper` CSS 是 `position:fixed; top:0; left:0; width:100%; height:100%` —— 永远铺满整个窗口。`petPos` 是死状态。
- **修复**:
  1. 布局重构: `.pet-char-wrapper` 收缩到 canvas 尺寸 (400×600), `position:absolute`, 用 `transform: translate(petPos.x, petPos.y)` 定位。窗口本身保持透明大窗口。
  2. 窗口内拖拽: mousedown 记录起点 + 设置拖拽阈值; mousemove 超过阈值才 `setIsBeingDragged(true)` 并更新 `setPetPos`; mouseup 调 `physics.release()` 进入自由落体。
  3. RAF 循环里把 `petPos` 绑到 wrapper 的 `transform`。
  4. 删除 `-webkit-app-region: drag` (Electron 专用, Tauri 无效)。
  5. 区分"点击(摸头/戳身体)"与"拖拽": 仅当鼠标移动超过 ~5px 才进入拖拽, 否则放行给 Live2D hit 检测 (见 FIX-M)。
- **验收**: 左键按住拖动 → 角色在窗口内跟随; 松手于半空 → 下落 + 弹跳; 静止点击 → 正常摸头/戳身体。
- **文件**: src/App.tsx, src/styles.css

### FIX-F: 发消息显示"..."后消失 (用户 3.1)
- **现象**: 输入回车后显示"..."然后气泡消失, 看不到回复。
- **根因 (已验证)**:
  1. 浏览器模式: `invoke("send_message")` 无后端 → 抛错 → catch 里 none of `includes(...)` 匹配 → `showBubble("...", 3000)`。
  2. Tauri 模式下若仍失败: 对话管道调 3 次 LLM (Gate→Extractor→主对话), 若 Gate/Extractor 的 JSON 解析失败, 错误信息不匹配现有分支, 同样落到"..."。
- **修复**:
  1. 前置: 确保 Tauri 模式运行 (FIX-0)。
  2. catch 兜底: 未匹配的错误 → `showBubble("（连接出了点问题…）", 5000)` + `console.error("[Conversation]", e)` 带完整堆栈。
  3. Gate/Extractor JSON 解析容错 (FIX-O): 去除 markdown 代码围栏、截取首个 {...}、try-catch 兜底。
- **验收**: Tauri 模式下发送消息 → 真实 LLM 回复出现在气泡; 失败时有可读错误提示。
- **文件**: src/App.tsx, src-tauri/src/mind/gate.rs, src-tauri/src/mind/extractor.rs

### FIX-G: 思考圆点看不到 (用户 3.2)
- **现象**: 回车后看不到跳动的圆点。
- **根因 (已验证)**: `isThinking` 置 true 后, 错误立即返回又被置 false, 闪现太短; 且 `thinking-dots` 的 `bottom:290px` 与 input-bubble 重叠可能被遮挡。
- **修复**:
  1. `isThinking=true` 后保证最少显示 500ms (即便快速出错/返回)。
  2. 圆点位置移到角色上方 (与对话气泡同槽位), 不与输入框重叠。
- **验收**: 即便快速失败, 思考圆点也可见 ≥500ms。
- **文件**: src/App.tsx, src/styles.css

### FIX-H: 气泡样式单一 (用户 5.2)
- **现象**: 气泡永远是同一种出现方式。
- **根因 (已验证)**: `bubbleClassForMood()` 只在 `handleSend` 的 LLM 回复时调用; 其余所有 `showBubble` 调用都传空字符串 (默认无情绪样式)。
- **修复**: 所有 `showBubble` 调用都带情绪样式:
  - 摸头 → `bubble-happy`
  - 戳身体分级 → `bubble-worried`
  - 深夜提醒 → `bubble-sad`
  - 欢迎语 → `bubble-calm`
  - 主动跟进 → `bubble-calm`
- **验收**: 不同场景气泡有不同的进场动画/圆角/透明度。
- **文件**: src/App.tsx

### FIX-I: 摸头气泡位置 + 尾巴 + 透明度 (用户 2.1 / 5.4 / 5.5 / 5.6)
- **现象**: 摸头文字出现在角色中间; 透明度不够; 没有指向角色的尾巴。
- **根因 (已验证)**: `.chat-bubble` 和 `.input-bubble` 共用 `bottom:280px; left:50%; transform:translateX(-50%)` 同一居中位置; 背景近不透明; 无 `::after` 尾巴。
- **修复**:
  1. 引入气泡位置变体: `showBubble(text, dur, style, position?)` 或独立的 petting-bubble。摸头气泡定位在头部左上角 (相对 canvas 顶部偏移)。
  2. 提高透明度: `--bubble-bg: rgba(255,255,255,0.82)`。
  3. 加 CSS `::after` 小尾巴 (三角或小圆) 指向下方角色。
- **验收**: 摸头文字出现在头部左上方, 带尾巴指向角色, 更通透, 不遮挡角色中心。
- **文件**: src/styles.css, src/App.tsx

### FIX-J: 无启动欢迎语 (用户 6.1)
- **现象**: 启动没有欢迎语。
- **根因 (已验证)**: 后端启动 2s 后 `emit("bubble-show")`; 浏览器模式无后端 → 收不到; Tauri 模式下 listener 异步注册, 可能与 emit 竞态。
- **修复**: 前端兜底 —— useEffect 里设 2s 定时器, 若未收到后端 `bubble-show` 则前端自己冒欢迎语; 收到则取消兜底。
- **验收**: 启动约 2s 内出现欢迎语 (Tauri / 浏览器均覆盖)。
- **文件**: src/App.tsx

### FIX-K: 导出记忆卡住 (用户 7.1)
- **现象**: 点导出显示"记忆导出中…"然后无后续。
- **根因 (已验证)**: `invoke("get_debug_snapshot").then(...).catch(() => {})` —— catch 静默吞错; 浏览器模式 invoke 失败 → 卡在"导出中"。
- **修复**:
  1. catch → `showBubble("导出失败了…", 3000)` + `console.error`。
  2. 建议改用 Tauri `dialog` API 让用户选保存路径 (而非浏览器 Blob 下载)。
- **验收**: 失败时有错误气泡; 成功时 (Tauri) 文件正常保存。
- **文件**: src/App.tsx

## 前一轮审计遗漏的问题 (本审计补充)

### FIX-L: `-webkit-app-region: drag` (Electron 残留)
- `.pet-char-wrapper` 带 `-webkit-app-region: drag` —— Electron 专用, Tauri 无效, 可能干扰事件。删除。随 FIX-E 一并处理。
- **文件**: src/styles.css

### FIX-M: 点击与拖拽冲突 (重要)
- **现象/风险**: `onMouseDown={handleDragStart}` 与 Live2D hit 检测 (`model.on("hit")` → onHeadClick/onBodyClick) 绑在同一 wrapper。每次按下都会触发拖拽逻辑, 摸头/戳身体会被拖拽抢占; 双击开输入框前也会先触发两次 mousedown。
- **修复**: 引入移动阈值 (~5px) 区分点击 vs 拖拽; 仅移动超阈值才进入拖拽, 否则放行给 hit 检测。与 FIX-E 一并实现。
- **文件**: src/App.tsx

### FIX-N: 注意力命中区域错误
- **根因**: `petRef` 绑在铺满全窗口的 `.pet-char-wrapper` 上, `getBoundingClientRect()` 返回整个窗口尺寸 → `computeAttention` 把整屏当宠物, "Focused" 几乎恒真, 三态判定失真。
- **修复**: 用实际 canvas/模型 bounds 计算 attention (或单独的命中元素 ref)。
- **文件**: src/App.tsx

### FIX-O: Gate/Extractor JSON 容错 (支撑 FIX-F)
- LLM 返回非标准 JSON (带 markdown 围栏、多余文本) 时解析失败。加正则提取首个 {...} + 去围栏 + try-catch。
- **文件**: src-tauri/src/mind/gate.rs, src-tauri/src/mind/extractor.rs
