### 2.3 视线不回正: 鼠标到角落时她的视线还看向角落

**根因**: 两套系统在并行运行, 互不相干。

1. `pixi-live2d-display` 库有**内置鼠标追踪**, 自动让模型头部/眼睛跟随鼠标, 无论距离多远。
2. 我们的 `computeAttention()` 函数 ([attention.ts](/C:/Users/SunJialei/Documents/桌宠/src/animation/attention.ts)) 正确计算了三态 (Focused/Peripheral/Ignored)。
3. 但 attention 状态**存进了 React state, 从未传给 Live2DCanvas**, 也**从未用来控制模型**。
4. 库的内置追踪不知道我们的三态系统, 所以永远追踪鼠标。

**修复方案**:
- 方案 A (推荐): 关闭库的自动追踪, 用 `computeHeadAngle()` 手动设置 Live2D 参数。Ignored 时角度归零 (回正)。需要每帧通过 `model.internalModel.coreModel.setParameterValueById('ParamAngleX', ...)` 更新。
- 方案 B: 保留库追踪, 但设置追踪范围。`pixi-live2d-display` 支持 `model.interactive = false` 关闭自动追踪, 然后手动接管。

修改文件: `src/Live2DCanvas.tsx` (接收 attention + mousePos 作为 props), `src/App.tsx` (传递 attention 状态)

### 2.10 + 第十节: 无法拖拽, 物理系统无效

**根因 A (拖拽)**: `handleDragStart` ([App.tsx:223](/C:/Users/SunJialei/Documents/桌宠/src/App.tsx)) 调用 `getCurrentWindow().startDragging()`。这是 Tauri API, 移动的是**整个操作系统窗口**, 不是窗口内的角色。设计文档要求的是角色在屏幕上自由移动。即使 Tauri 正常运行, 拖拽的也只是窗口位置。

**根因 B (物理/空间)**: `petPos` 状态被 Physics 和 SpatialMemory 模块更新, 但**从未应用到任何 DOM 元素**。`pet-char-wrapper` 的 CSS 是 `position: fixed; top: 0; left: 0; width: 100%; height: 100%` —— 永远填满整个窗口。`petPos` 是死状态。

**根因 C (浏览器模式)**: 在浏览器中, `getCurrentWindow()` 不存在。

**修复方案**:
1. 拖拽: 用 React 的 mouse 事件实现窗口内拖动。鼠标按下 → 记录起始位置 → mousemove 时更新 `petPos` → 应用到 wrapper 的 `transform: translate(x, y)`。
2. 物理渲染: Physics/Spatial 模块输出的 `petPos` 必须绑定到 wrapper 的 CSS transform。
3. 窗口设计: 窗口应该很大 (覆盖大部分屏幕, 透明), 角色在窗口内自由移动。或者改用多窗口方案。

```typescript
// 修复后的拖拽:
const onDragStart = (e: React.MouseEvent) => {
  if (e.button !== 0) return;
  const startX = e.clientX - petPos.x;
  const startY = e.clientY - petPos.y;
  setIsBeingDragged(true);
  // 在 mousemove 中: setPetPos({ x: e.clientX - startX, y: e.clientY - startY })
};

// 渲染时应用位置:
<div
  className="pet-char-wrapper"
  style={{ transform: `translate(${petPos?.x}px, ${petPos?.y}px)` }}
>
```
修改文件: `src/App.tsx`, `src/styles.css`

### 3.1 发消息显示 "..." 后消失

**根因 A (浏览器模式)**: `invoke("send_message")` 无后端 → 抛出错误 → catch 块匹配不到已知错误模式 → 显示 "..."。

**根因 B (Tauri 模式)**: 对话管道调用了 3 次 LLM (Gate → Extractor → 主对话)。如果 Gate 或 Extractor 的 JSON 解析失败 (LLM 返回非标准格式), 错误信息如 `"Failed to parse gate response..."` 不匹配任何已知错误模式 → 显示 "..."。

**根因 C**: 错误处理中, `showBubble("...", 3000)` 的 "..." 不包含任何有用信息, 用户无法知道出了什么问题。

**修复方案**:
1. 优先: 确保用 `npm run tauri dev` 运行
2. 错误处理改进: catch 块中显示更多调试信息 (开发模式下)
3. Gate/Extractor JSON 解析增加 fallback (见下方独立修复)

```typescript
// 改进错误处理:
catch (e) {
  setIsThinking(false);
  const errMsg = String(e);
  if (errMsg.includes("not configured")) {
    showBubble("还没有配置好连接...", 5000);
  } else if (errMsg.includes("parse") || errMsg.includes("Parse")) {
    // JSON 解析失败, 说明 LLM 返回格式不对
    showBubble("我...有点没听懂...", 5000);
    console.error("[Conversation] Pipeline error:", errMsg);
  } else {
    showBubble("...", 3000);
    console.error("[Conversation] Unknown error:", errMsg);
  }
}
```
修改文件: `src/App.tsx`

### 第四节: FSM 微行为整体失效

**根因**: 架构层面断链。

1. FSM 逻辑正确运行 ([fsm.ts](/C:/Users/SunJialei/Documents/桌宠/src/animation/fsm.ts)): 每 2.5 秒 tick, 选择微行为, 更新 `behavior` state。
2. CSS 动画定义存在 ([styles.css](/C:/Users/SunJialei/Documents/桌宠/src/styles.css)): `.pet-svg.yawn`, `.pet-svg.stretch` 等。
3. **但 CSS 类绑定的是 `.pet-svg` 元素, 当前渲染用的是 Live2D `<canvas>`**。
4. Live2DCanvas 组件**不接收 `behavior` prop**, 不知道 FSM 状态变了。
5. 没有代码把 FSM 状态映射到 Live2D `model.motion()` 调用。

**修复方案** (需要较大改动):
1. Live2DCanvas 接收 `behavior: BehaviorState` prop
2. 建立 FSM 状态 → Live2D 动作的映射表:
```typescript
const FSM_TO_MOTION: Record<BehaviorState, string | null> = {
  Idle: null,              // 不触发动作, 恢复呼吸
  Blink: null,             // Live2D 内置自动眨眼
  LookAround: "Tap",       // 触发头部动作
  TiltHead: "Flick",       // 触发歪头
  Yawn: null,              // 需要自定义或用表情替代
  Stretch: "Tap",          // 伸懒腰
  Sway: null,
  Talking: null,           // 由对话流程单独处理
  Thinking: "Tap",
  Embarrassed: "F06",      // 害羞表情
  // ...
};
```
3. 在 Live2DCanvas 中监听 behavior 变化, 调用对应 motion/expression
4. 检查 Haru 模型的 model3.json 可用动作列表, 确保映射的 motion 名存在

修改文件: `src/Live2DCanvas.tsx`, `src/App.tsx`, 可能需要调整 `src/animation/fsm.ts`

### 6.1 无启动欢迎语

**根因**: 欢迎语由 Rust 后端发出 (`lib.rs:107`):
```rust
std::thread::spawn(move || {
    std::thread::sleep(std::time::Duration::from_secs(2));
    let _ = handle.emit("bubble-show", "你好呀！我是你的桌宠。");
});
```
浏览器模式无后端 → 事件不发出。
Tauri 模式下应该工作, 但需要验证事件监听器的竞态: `listen("bubble-show")` 是异步注册的, 如果注册晚于 emit, 会漏接。

**修复方案**:
1. 优先: 确保 `npm run tauri dev` 运行
2. 前端兜底: 在 useEffect 中加一个前端延迟欢迎语 (如果 3 秒内没收到后端的, 前端自己显示)

```typescript
// 前端兜底欢迎语
const fallbackTimer = setTimeout(() => {
  showBubble("你好呀！", 5000, "bubble-calm");
}, 2000);
// 如果收到后端的 bubble-show, 取消前端兜底
listen("bubble-show", (event) => {
  clearTimeout(fallbackTimer);
  showBubble(event.payload);
});
```
修改文件: `src/App.tsx`
