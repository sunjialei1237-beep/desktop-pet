# 桌面模式实测清单 (v2)

> 前置: 必须用 `npm run tauri dev` 启动 (会弹出桌面窗口, 无地址栏)。
> 千万不要再用浏览器打开 localhost:1420 —— 之前的失效大半是浏览器模式无后端导致。
> 已加浏览器模式检测: 若在浏览器打开, 会冒泡提示 "请在桌面模式下运行"。

测每项后, 请回我: 通过 / 仍有问题 (附现象) / 新发现。

---

## 一、运行环境与启动

1. **启动方式**: `npm run tauri dev` 弹出透明桌面窗口, 桌宠可见, 无崩溃/panic。
2. **欢迎语**: 启动约 2 秒内, 桌宠冒出欢迎气泡 (如 "你好呀! 我是你的桌宠")。
   - 若后端事件没到, 前端兜底也会冒 (约 2 秒)。
3. **浏览器模式提示**: 若你在浏览器打开 1420, 应冒泡 "请在桌面模式下运行" (顺带验证检测生效)。

## 二、交互 (视线 / 摸头 / 戳身体 / 输入框 / 拖拽)

4. **视线跟随 (FIX-A)**: 鼠标在窗口内移动, 桌宠头/眼朝鼠标方向偏转。
5. **视线回正 (FIX-A, 重点)**: 把鼠标移到离桌宠 >200px 的角落, 停住。
   - 预期: 约 1 秒内视线平滑回到正前方 (不再死盯角落)。
   - 这是你上次明确反馈的问题, 优先确认。
6. **摸头气泡 (FIX-I, 重点)**: 单击桌宠头部。
   - 预期: 冒出 "嘿嘿…/谢谢你~/抹抹~" 之类。
   - 位置: 应出现在头部左上方, 带小尾巴指向角色, 不再压在角色正中。
   - 透明度: 比之前更通透。
7. **戳身体反应 (FIX-C, 重点)**: 单击桌宠身体。
   - 预期: 每次戳都有反应 (动作 + 气泡), 不是只在第 3 次才说话。
   - 分级: 1 次 "?" 惊讶 / 2 次 "嗯…" 皱眉 / 3 次 "别戳了啦!" 生气。
8. **输入框 placeholder (FIX-D)**: 双击桌宠, 弹出输入框。
   - 预期: 能清楚看到 "想和我说什么?" (之前白字白底看不见)。
9. **拖拽 (FIX-E + FIX-M, 重点)**: 左键按住桌宠拖动。
   - 预期: 桌宠在窗口内跟随鼠标移动 (不是拖动整个窗口)。
   - 松手于半空 → 下落 + 轻微弹跳。
   - 注意: 点击与拖拽已用 5px 阈值区分 —— 轻点不触发拖拽, 拖动才移动。

## 三、对话 (需已配置 DeepSeek API key)

10. **发消息有真实回复 (FIX-F, 重点)**: 双击 → 输入一句话 → 回车。
    - 预期: 出现思考圆点 (跳动), 约 1~3 秒后桌宠冒出真实 LLM 回复。
    - 不再出现 "..." 然后消失。
11. **思考圆点可见 (FIX-G)**: 回车后应能看到跳动的圆点, 且至少持续约 0.5 秒 (即便回复很快)。
12. **错误可读 (FIX-F)**: 若 API key 未配或网络异常, 应冒出可读提示 (如 "连接出了点问题…"), 不再是 "..."。

## 四、FSM 微行为 (第四节整体)

13. **自动动作 (FIX-B, 重点)**: 静置观察约 30 秒~1 分钟。
    - 预期: 桌宠会自己切换动作/表情 (每 2.5 秒 tick), 不再静止。
    - 注意: Haru 模型只有 Idle×3 + Tap×2 两组动作, 所以视觉差异主要靠 Tap 手势 + 表情变化体现, 不如换装丰富 —— 这是模型资源限制, 非 bug。

## 五、气泡形式与情绪

14. **气泡形式多样 (FIX-H)**: 触发不同场景, 观察气泡进场动画是否不同。
    - 摸头 → 欢快弹出 (bubble-happy)
    - 深夜提醒 → 失落下沉 (bubble-sad, 需凌晨测)
    - 欢迎语 → 平静淡入 (bubble-calm)
    - 戳身体生气 → 颤抖 (bubble-worried)

## 六、功能

15. **导出记忆 (FIX-K)**: 右键 → 导出记忆。
    - 预期: 成功则下载 JSON 文件; 失败则冒泡 "导出失败了…" (不再卡在 "导出中…")。
16. **Debug Panel**: 按 F12, 弹出调试面板。
    - 观察 mood / energy / stress / loneliness 数值。
    - 互动几下后看 closeness 有没有涨。
    - 这是第九节情绪系统的验证窗口。
17. **右键菜单**: 右键 → 三个选项 (导出/休息/关闭) 可见可点。

## 七、已知限制 (验收时心里有数, 非问题)

- Haru 模型动作有限 (Idle×3 + Tap×2), FSM 微行为视觉差异靠 Tap + 表情, 不如多动作模型丰富。
- 拖拽落体的 "地面" 是 window.innerHeight - 48 - 120, 桌宠可能停在窗口偏下位置。
- 视线回正靠每帧覆盖库的自动追踪, 平滑约 1 秒。
