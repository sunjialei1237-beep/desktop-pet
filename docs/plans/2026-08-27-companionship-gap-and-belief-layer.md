## 0. 一句话诊断

**工程完成度严重超配，产品核心体验严重欠配。**

"她记得你"做到了工业级（记忆闭环 / 防幻觉 / 成本 / 稳定性 / 工具层 / 安装包全通）；
"她活着"——陪伴产品唯一真正的价值——基本没做。

**当前产品本质 = "带记忆的聊天 widget" + "会眨眼呼吸的桌面挂件"，两层是割裂的。**
记忆只活在文字里，生命只活在待机动画里，两者从未在"身体"这一层汇合。
所以她记得你，但不看你、不靠近你、不为你的到来而高兴、不为你的离开而低落 → **感觉不到陪伴**。

## 1. 陪伴感的五个具体缺口（附代码证据）

### 缺口 1：所有主动行为都是文字气泡，身体永远不表达

**证据**：`lifecycle/loop_runner.rs` 的全部"生命感"行为——`check_goodmorning` / `check_goodnight` /
`check_weekly_summary` / `check_landmark` / `check_presence_transition` / `check_lonely_nudge`——
最终一律 `app.emit(...)` 一个事件，到 `App.tsx` 全部转成 `showBubble()`。

**她永远不会向你走来。** 设计文档 §9.2 的"走到你身边""主动窥屏""坐窗口边缘"，一个都没做；
§6.8 的"窝 / 领地感"没做；Walk 状态更是在 2026-08-08 被主动砍除。

→ **"聊天机器人"与"陪伴者"最本质的区别，在当前系统里等于零。**
文字是"说"，身体是"在"。陪伴感全部来自后者。

### 缺口 2：身体是"活的"，但不是"有情绪的"

**证据**：`src/SpineCanvas.tsx` 的身体动作只有——呼吸（`body_breath`）、眨眼、微笑、
耳朵/尾巴一次性摆动、**水平方向视线跟随**（±10° 头 + ±3° 身体，`GAZE_RANGE=320`）。

- 视线只有水平，没有上下（2D 骨骼技术限制，注释已说明"头会飞"）；
- `emotion → 动画` 只实现了"深夜动作变慢（`ticker.speed`）+ 自动睡觉"这一条；
  设计 §6.10 的"开心=蹦跳 / 低落=低头慢动作 / 害羞=拘谨"基本没做；
- `animation/fsm.ts` 的状态全是待机微行为（blink/yawn/stretch/hum/peek），
  没有一个状态表达"她为你高兴"或"她有点想你"。

→ **情绪在数据库里是连续向量（mood/energy/social/stress/loneliness/rest_need），在屏幕上却是一张不变的脸。**

### 缺口 3：第一印象缺失

**证据**：设计 §7.6 原文——"初次登场**极其重要**，定下整个产品调性……她从任务栏爬上来？从天上掉下来？"
实际 first-run = `SetupWizard`（填 API key）→ `ONBOARD_QUESTIONS`（4 个表单问题：称呼/性格/关系/名字）。

→ **没有"她第一次进入你屏幕"的时刻。** 用户第一次见到的是角落里的狐狸挂件 + 一份问卷。情感锚点 = 0。

### 缺口 4："懂你"层太浅 —— 她记得你，但没在"琢磨你"

**证据（soul 层四块代码全读过）**：

| 层 | 现状实现 | 病 |
|---|---|---|
| Facts | `category/key/value/confidence` + 时间有效性 | ✅ 健康（存得准、取得回） |
| Episodes | `summary/importance/emotion/strength` + 衰减 | ✅ 健康 |
| **人格成长** | `persona_traits.trait_key`，**一个裸关键词** | ❌ 成长 = 一串形容词标签云 |
| **内心念头** | `internal_thoughts`，`surface_thoughts` 说完即 `mark_surfaced` | ❌ 一次性，说完即销毁，无法发展 |
| **关系理解** | `relationship_reviews` 每 15 条覆盖一份，retrieval 只注入 latest | ❌ 只有当前快照，没有"理解的历史" |
| **巩固** | `consolidation.rs` 压缩 episode → 只回填 **facts** | ❌ 只压缩事实，不产生任何解释 |
| **认知透镜** | `system.txt` 里**写死的三条**（"人类说没事的时候往往不是真的没事"…） | ❌ 作者写的，不是长出来的 |

看代码就明白：

```rust
// db/persona.rs — 所谓"adaptive trait"，就是 upsert 一个关键词 + 一个置信度
ON CONFLICT(trait_type, trait_key) DO UPDATE SET confidence = ?4, ...

// soul/monologue.rs — 念头说完就标 surfaced，永不再返回
for t in &unsurfaced { mark_surfaced(conn, &t.id, &now)?; }

// soul/review.rs — 新 review 只 insert，retrieval 取 latest → 旧的等于被覆盖
relationship_reviews::insert(...)
```

→ **她"记得你"，但没有"惦记你"。** 这两者的差别，就是"数据库"和"人"的差别。
而且 —— **`system.txt` 里已经有"认知透镜"这个概念，但它是写死的常量，所以它不可能变。**

### 缺口 5：没有声音

**证据**：`audio/soundManager.ts` 只有 Foley 音效（摸头"嗯？"/ 落地 / 启动 hi）；TTS 在设计里被标"二期可选"。

→ **一个你必须"读"的陪伴者，本质上还是个聊天窗口。** 声音是"在场"最便宜的载体。

### 附：粘性对照表

| 粘性来源 | 现状 | 结论 |
|---|---|---|
| 回访钩子 | 早安/晚安是**一次性、单向、且只在"你恰好在电脑前"才触发** | 没有"她在等你"的机制 |
| 关系成长 | closeness 0-100、7/30/100 天里程碑**全是隐藏数字**，无 unlock 时刻 | 用户看不到"我们变熟了" |
| 惊喜 | Serendipity 有（1/3 × 弱相关带）但行为是 `planner.rs` 5 条死规则 | 没有"她突然想起你忘了的事" |
| 照料循环 | Liri 主动选"不黏人、不养成"（有品位的正确选择） | 但代价是失去 Tamagotchi 式粘性 |
| 情感依赖 | welcome-back / lonely 存在但全是气泡，且 30-60min 节流 | 她不会让你觉得"卸载了她会难过" |

**关键结论：Liri 现在两头不靠。** 既不是能养的电子宠物（没照料钩子），又不是够深的陪伴（没情感表达）。
"安静、观察、不黏人"这条高端审美路线（对标《Her》的 Samantha，不是 QQ 宠物），
**必须用极致的情感表达来补**——否则结果就是：不黏人 + 不深刻 = 被遗忘。

## 2. 根因：两层

### 根因 A（架构层）：系统只有「记录」和「取回」，没有「解释」和「改主意」

**记忆被当成数据库用（存得准、取得回），而不是当成理解用（想通了什么、改变了什么看法）。**

所以它长不出东西，不是因为 LLM 不行，是因为**架构里根本没有"信念"这个概念可以生长**：

- `trait_key` 是**标签**不是**判断** → 没有内容可长
- `thought` 说完就**销毁** → 没有时间可以长
- `review` 是**快照**被覆盖 → 没有历史可以长
- 透镜是**写死的常量** → 它就不能变

> **真正的人的成长不是"记住更多事实"，而是"改变解释框架"。**
> 同一件事，三个月前理解成一个意思，现在理解成另一个意思——这才是"长大"。
> 当前系统里，**没有任何一层允许"对同一件事的看法被改写"**。

### 根因 B（执行层）：项目发生了「陪伴 → 工具」的漂移

翻 63 个续次的精力分布，大量投在：
- 工具层（search_web / open_application / 文件读写 / edit_file / 笔记 / 授权链）
- 成本优化（前缀缓存 / 按角色分模型 / 命中率）
- 基础设施（NSIS 安装包 / 设置面板 / 向导 / 便携 zip）
- 边缘 bug（拖拽物理 / 点击穿透 / 窗口吸附）

这些全是"有用"，不是"有趣"。设计原则 #10 白纸黑字"**先增加生命感，不优先增加功能**"，
Kill List 也把工具排在最后。但实际执行里工具层拿了不成比例的注意力——**而且很多需求是用户自己提的**
（"帮我打开抖音""帮我看代码""重构快捷方式"）。

> **这本身就是症状：当陪伴不够打动人的时候，人会本能地去做"让它有用"，然后它就真的变成了一个工具。**
> 这是陪伴类产品的经典死亡模式（QQ 宠物后期也是这么变成骚扰工具的）。

## 3. 关于狐狸形象与动作的决策

### 3.1 现状与用户判断

用户：Spine 骨骼动画做"打招呼 / 坐下 / 走路"这类动作门槛极高（本质是**动画师**的工作，不是程序员的工作），
做出来效果也不理想 → 全部搁置 → 导致动作刻板。

**这个判断是对的**：人形 / 兽形角色做不了代码级 squash-and-stretch，程序化 transform 对它们表达力有限。

### 3.2 但有第三条路：不要把情绪押在「动作」上，押在「状态」和「累积」上

> **"生动"不等于"会动"。而且对"成长"这个主题，"累积"比"运动"强得多。**

桌上的玩偶一个动作都不会做，但陪你三年、落了灰、旁边多了你随手放的钥匙——你会对它产生感情。
情感不来自它动了，来自**它身上有你留下的痕迹**。

**用「状态和累积」表达，而不是用「动作」表达：**

| 想表达 | 不要指望动作 | 改成（全部不需要 K 帧） |
|---|---|---|
| 开心 | 跳起来 | 光更暖 / 毛色更亮 / 尾巴姿态微调 |
| 难过 | 低头 | 整体色调偏冷 / 变灰 / 光照变暗 |
| 困 | 打哈欠 | 已有（速度变慢）+ 色调变暖黄 |
| 害羞 | 捂脸 | 柔光 / 泛红 tint + 整体轻微缩小 |
| **成长** | —— | **窝里慢慢堆东西 / 她多了条围巾 / 笔记本变厚** |
| **关系变熟** | —— | **她的位置从屏幕角落慢慢挪向中央** |
| **她有自己的生活** | —— | **窝边放着她的"收藏"：一片叶子、一颗石子、一张纸条** |

这些全是**静态素材 + 简单摆放 / 调色 / 位移**，纯程序可做，且**在"陪伴久了"这个维度上比任何骨骼动画都有力量**。

### 3.3 如果要重做形象，方向不是"像素风"

- **不要换像素风**：像素动画要逐帧画，工作量更大、更难。
- 推荐 **"软体 / 团子 / 毛球 / 小幽灵"类**：这类形象的可爱与情绪**完全来自 transform**
  （挤压拉伸 / 弹跳 / 倾斜 / 变色），是程序化动作的完美匹配，物理感最强。
  参考：Duolingo 的 Duo、割绳子的 Om Nom、Slack emoji。

### 3.4 架构层面的好消息

Mind-Body 解耦（原则 #5）在这里派上大用场：**换形象 = 只换 `SpineCanvas.tsx` 一个组件 + 资产**。
Mind / Soul / 记忆 / 对话 / `system.txt` 的人格**全部不动**。

**当前建议**：先做 3.2 的"状态与累积"（成本极低、复用现有资产），验证生命感是否够；
若不够再换软体形象（架构上只是换一个组件）。

## 4. 核心方案：新增「信念层」（Belief Layer）

> 这是**唯一能让产品从"数据库"变成"人"的改动**，而且同时解决缺口 4 与自动冒泡死板两个问题。

### 4.1 数据模型（新表 `beliefs`）

```sql
CREATE TABLE beliefs (
  id               TEXT PRIMARY KEY,
  -- 一句第一人称的自然判断（不是标签，是内容）
  statement        TEXT NOT NULL,        -- "他嘴上说没事的时候，通常是有事的"
  kind             TEXT NOT NULL,        -- about_user | about_us | about_world | about_self
  confidence       REAL NOT NULL,        -- 0..1，随证据升降
  -- 证据（可追溯到具体 episode）
  evidence         TEXT,                 -- JSON [{episode_id, note, at}]
  -- ⭐ 改口史 —— 全表最重要的字段
  revision_history TEXT,                 -- JSON [{was, now, why, at}]
  formed_at        TEXT NOT NULL,
  updated_at       TEXT NOT NULL,
  status           TEXT DEFAULT 'active' -- active | revised | retired
);
```

`revision_history` 让**"改口"成为一等公民**——"我以前以为你…后来觉得你…"这件事在库里是一条真实数据。

### 4.2 生成与修订（复用现有反射调用，**零新增 LLM 成本**）

`reflection.rs` 每天跑一次，当前输出 `new_traits` + `internal_thoughts`。
**只需扩展 JSON schema**：

```json
{
  "beliefs": [
    {"action":"form",   "kind":"about_user", "statement":"...", "confidence":0.5, "evidence":["ep_123"]},
    {"action":"revise", "id":"b_12", "statement":"新看法", "confidence":0.7, "why":"因为他这周..."},
    {"action":"retract","id":"b_7",  "why":"反例出现了"}
  ]
}
```

**关键（当前代码做不到的一点）**：`reflection.rs` 目前输入里只有 `persona_text`（一串 `trait_key`），
**它看不到"可以被推翻的具体判断"**。必须把现有 beliefs 连同 evidence 一起喂进去，它才可能 revise。

> 成本：**零新增调用**。只是同一个反射请求的 JSON 变长几十 token。

### 4.3 注入方式：区分「事实」和「透镜」（精髓）

| 段 | 含义 | 提示词语义 |
|---|---|---|
| `[Memories]` | **我知道的事** | 只可引用，不可编造 |
| `[你眼中的他]` | **我怎么看他** | **用它去理解他这轮说的话** |

```
[你眼中的他 — 这些是你慢慢形成的看法，不是他告诉你的]
- 他嘴上说"没事"的时候，通常是有事的。（你观察过三次，比较确定）
- 他半夜写代码不是因为喜欢，是白天静不下来。（还不太确定，你在看）
- 你以前以为他不爱说话，后来发现他只是慢热。（你改过看法）
```

最后一条——**"你以前以为…后来发现…"**——就是成长的可见痕迹，会自然变成台词：
「我以前还以为你不爱说话呢。」

**缓存友好**：信念每天才变一次，可放**静态前缀**（同一天内字节稳定），完全兼容现有的前缀缓存纪律。

### 4.4 对照示例（同一个场景，两种人格）

用户三次焦虑地说起找工作：

**现在（数据库）**
- 存 3 条 episode + 1 条 fact（goal: 实习）
- 第 4 次她说：「又在忙实习的事呀」（复述）
- **它没有变**

**加信念层之后**
- 反射产出 belief：`"找实习对他来说不只是找份工作，是他证明自己不是废物的方式"`（confidence 0.7，evidence 3 条）
- 第 4 次她说：「你最近是不是把这事看成一场考试了」——**这是视角，不是复述**
- 两周后拿到 offer，反射 revise 这条信念：
  `{was: "他在用实习证明自己", now: "他其实比自己以为的更有底气", why: "他拿到 offer 后第一反应是松了一口气，不是狂喜"}`
- 以后再谈工作，她的语气**变了**——因为她看你的方式变了

**这就是"长出来"。** 不靠新功能，靠的是**允许旧看法被改写**。

## 5. 自动冒泡为什么死板 + 改法

### 5.1 诊断

`loop_runner.rs` 的全部冒泡触发点：

| 触发 | 驱动类型 |
|---|---|
| 早安 / 晚安 / 周日总结 / 里程碑 | **日历**（到点了） |
| welcome-back | **存在**（你回来了） |
| lonely-nudge | **阈值**（孤独 > 0.6） |
| pending 提醒 | **事件**（你之前提的） |

**所有动机都在"外部时钟或计数器"上，没有一个在"她的想法"上。** 于是：

1. **冒泡没有"由头"**——`lonely-nudge` 给 LLM 的上下文是"用户孤独"，它只能生成泛泛的话（"想你了"）。
   真人开口永远有由头："对了，你上次说的面试怎么样了？"
2. **没有"没说完的线头"**——真人对话是一堆未了的事。她说完「早安」就结束了，
   从不问"我上次问你的那件事，后来呢"。
3. **她没有自己的议程**——所有冒泡都关于你，没有"我今天有点没精神"这种**她自己的状态外溢**。
4. **渠道单一**——永远一个文字气泡，没有身体、没有声音、没有"她动了"。
5. **节流是时间闸门（30-60min）而非语义闸门**——既会在无聊时刻话说多，又会在最有意义的时刻
   （你刚好完成一件事的那一秒）错过。
6. **不留痕迹**——发完就消失，不期待你回应，也**不追踪你没回应**。

> **因为没什么在她心里长出来，所以冒泡只能靠时钟硬挤——这就是死板的根源。**

### 5.2 改法

1. **冒泡前必须先有由头**：从 beliefs / threads / 最近 episode 里挑一条**具体的**，喂给生成 prompt。
2. **没有由头就不冒泡**——这本身就是原则 #12（沉默也是表达），而且会让她每次开口都有分量。
3. **引入 threads（未了的事）**：她可以有自己挂着的线头。现成地基：
   `pending_events.origin` 已有 `user`/`pet` 两值，`pet_promise` 链路已在跑 → 扩展即可。
4. **加"her own agenda"**：偶尔冒泡是她自己的状态，不是关于你的。
5. **渠道多样化**：气泡 + 身体 + 声音组合。
6. **语义闸门替代时间闸门**：「有由头 + 不打扰 + 没刚说过」而不是「每 30 分钟最多一次」。
7. **追踪回应**：她冒泡后你没回，她记一笔（"他上次没接话"），下次不硬提。

## 6. 「什么表现形式最好」——按力量排序

| 排名 | 表现 | 为什么最强 | 成本 |
|---|---|---|---|
| 1 | **改口的痕迹**（"我以前以为你…"） | 唯一能直接证明"她有判断、且会变"的形式。真人不会说"我更新了用户模型"，但会说"诶我一直以为你…" | 低 |
| 2 | **被信念影响的行为** | 她说"我在琢磨你"是空的；她因为你加班而**选择不打扰**，你才感觉到 | 低 |
| 3 | **可累积的视觉痕迹** | ⭐ **对狐狸形象困境的解药**。窝里堆东西 / 多了围巾 / 笔记本变厚——不需要任何 K 帧 | 中 |
| 4 | **未了的事（threads）** | 她自己的牵挂："上次你说想学吉他，后来呢？" | 低 |
| 5 | **遗忘与抽象** | 细节淡出、结论留下："那天具体哪天我记不清了，就记得你特别高兴" | 低（consolidation 已有雏形） |
| 6 | **她自己的议程** | "我今天有点没精神"——她不是为了你而存在 | 低 |
| 7 | 动作 / 动画 | **排最后**。现在做不好，而且它不是关键 | 高 |

**结论：把精力从第 7 项移到第 1~3 项。** 前六项全是**数据 + 提示词 + 简单渲染**，
是程序员的主场，且没有一项需要动画师。

## 7. 落地路线

### P0 —— 信念层 MVP（约一周，零新增 LLM 成本）

1. 建 `beliefs` 表（含 `revision_history`）。
2. 扩展 `soul/reflection.rs` 的 prompt：**输入现有 beliefs** + 输出 `form/revise/retract`。
3. `db/persona.rs` 换掉「`trait_key` 标签云」→ 存**完整句子**（或并存，beliefs 独立成表）。
4. `mind/grounding.rs` 新增 `[你眼中的他]` 段（静态前缀；prompt 里讲清"这是透镜不是事实，用它理解他"）。
5. 单测锁语义：`form` / `revise`（旧看法进 `revision_history`）/ `retract`；JSON 兼容旧格式。

> 做完这四件事，她**当天晚上就会第一次"改口"**。

### P0 —— 冒泡治本（与上并行）

6. 冒泡前挑「由头」（belief / thread / 最近 episode）；**无由头不冒泡**。
7. 时间闸门 → 语义闸门。
8. 追踪"你没接话"。

### P0 —— 身体与声音（最高感知杠杆）

9. **事件 → 姿态反应**（复用现有 gaze / ear / tail / `triggerBehavior` 轨道）：
   - welcome-back → 抬头看向你 + 身体前倾
   - celebrate → 弹跳脉冲（y 方向阻尼振荡）
   - care（用户难过）→ 身体下沉 + 动作放慢
   - 早安 → 伸懒腰（`scaleX` 拉长 + `scaleY` 压缩回弹）
10. **情绪 → 持续姿态**（复用 gaze 的 `GAZE_TAU` 平滑模式做 lerp）：
    开心=上浮+呼吸 bob 加大 / 难过=下沉+微灰 / 困=前倾+幅度减小 / 紧张=呼吸变小+微抖。
11. **TTS 接入**（先覆盖 早安/晚安/欢迎回来/里程碑 几句仪式性的话）。

> 技术上全部是"代码驱动 transform + 缓动/弹簧"，不碰 Spine 编辑器、不 K 帧、不需要美术。
> 弹簧系统：一阶阻尼 `value += (target-value)*(1-exp(-dt/tau))` 用于姿态；
> 二阶带 velocity 的 spring 用于跳跃/惊吓（会有 overshoot，弹两下——生命感正来自这里）。

### P1 —— 一个月内

12. 关系成长可见：里程碑从"文字"升级为"她主动说 + 身体庆祝"；closeness 跨阈值时有一次明显的
    "变熟"行为（从拘谨坐远 → 放松坐近）。
13. 初次登场时刻（设计 §7.6）。
14. 可累积的视觉痕迹（窝 / 物件 / 她身上可见的变化）。
15. threads：她自己的牵挂（复用 `pending_events.origin='pet'` 地基）。

### P2 —— 中长期

16. Curiosity / Habits（她注意到你的习惯并主动问）。
17. 空间 / 窝（她有家，聊完回窝，你回来她从窝里出来迎你）。
18. 声音全覆盖 + 语气起伏。
